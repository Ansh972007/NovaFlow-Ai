--------------------------------------------------------------------------------
1. WHAT IS THIS PROJECT?
--------------------------------------------------------------------------------

NovaFlow AI is an enterprise AI workspace. It gives teams one place to:

  • Chat with AI assistants
  • Build knowledge bases (RAG — Retrieval Augmented Generation)
  • Design visual AI workflows
  • Run tool-using agents
  • Schedule digests and automations
  • Fine-tune / evaluate models
  • Share workflows in a marketplace
  • Manage team, integrations, and analytics

It is a full-stack product: Next.js frontend + FastAPI backend + MySQL +
Redis + optional Milvus vector DB, runnable with one Docker Compose command.


--------------------------------------------------------------------------------
2. HOW TO RUN
--------------------------------------------------------------------------------

Docker (recommended — full stack):

  cd novaflow-ai
  docker compose up -d --build

  Web  : http://127.0.0.1:3000
  API  : http://127.0.0.1:3001
  Health: http://127.0.0.1:3001/health

  On Windows, prefer 127.0.0.1 instead of localhost.

Default login:
  Username : admin
  Password : admin123

Local scripts (deploy/):
  start.ps1          — start stack
  start-backend.ps1  — API only
  start-demo.ps1     — demo seed data
  start-prod.ps1     — production style

Dev frontend (without Docker web image):
  copy .env.example .env.local
  npm install
  npm run dev

8. WHAT THIS PROJECT DOES FOR THE USER (FEATURES)
--------------------------------------------------------------------------------

1) CHAT
   Talk to published AI assistants over WebSocket streaming.
   Supports RAG answers with citations when knowledge is linked.
   Can cancel in-flight responses.

2) APPS (ASSISTANT STUDIO)
   Create assistants, set system prompts, publish online,
   attach knowledge bases, view usage.

3) KNOWLEDGE (RAG)
   Upload PDF / TXT / MD / CSV.
   Chunk + embed documents.
   Hybrid search (vector + keyword).
   URL ingest and Q&A preview.
   Power accurate, grounded answers in chat/workflows.

4) WORKFLOWS
   Visual pipeline builder (trigger → retrieve → LLM → output).
   Live test runs over WebSocket.
   Version history / diff.
   Publish / unpublish.
   Collaborative presence.
   Webhooks and inbound Slack / Telegram triggers.

5) DIGESTS
   Schedule cron-based digests (retrieve → summarize → deliver).
   Enable / disable schedules and run-now.

6) AGENTS
   Save and run agents with tools such as:
   calculator, kb_search, summarize, translate, datetime,
   web_fetch, regex, json_parse, word_count.

7) MARKETPLACE
   Browse / share public workflows.
   Clone templates into your workspace.
   Rate and comment.

8) MODEL LAB / FINE-TUNE
   Datasets and training jobs.
   A/B model routes.
   Prompt drift checks.
   Deploy a fine-tuned model onto an assistant.

9) PROJECTS
   Group workflows + integration configs in a project hub.
   Run linked workflows from one place.

10) EVALUATION
    Build eval suites and cases (including CSV import).
    Schedule eval runs.
    Regression alerts (Slack / PagerDuty / Opsgenie / email).
    Compare runs and trends.

11) INTEGRATIONS
    Connect Gmail / SMTP, Jira, Slack, Discord, Linear,
    GitHub Issues, Telegram bots, email notify.

12) DASHBOARD & ANALYTICS
    Workspace stats, live pulse cards, usage charts,
    module launcher, workflow activity.

13) SETTINGS & TEAM
    Profile / security, LLM providers & limits,
    integrations health, workspace team roles
    (admin / editor / viewer).

14) DEVELOPER
    Create API keys for programmatic access.
    Proxy to backend under /api/v1.

15) DEMO MODE
    Without OPENAI_API_KEY, chat can return placeholder demo replies
    so the UI still works for exploration.

12. IMPORTANT NOTES (WINDOWS)
--------------------------------------------------------------------------------

  • Use http://127.0.0.1:3000 and http://127.0.0.1:3001
    (localhost can hit broken IPv6 / WSL relay on some Windows setups)

  • Docker Desktop must be running before `docker compose up`

  • If the UI looks old after rebuild: hard refresh (Ctrl+Shift+R)
    or open an Incognito window

  • Sibling bisheng-main/ folder is reference-only; NovaFlow does not
    need Bisheng at runtime
